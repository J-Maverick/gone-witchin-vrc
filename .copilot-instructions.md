# GoneWitchinHD - VRChat World Development Guidelines

This repository contains the Unity project for "GoneWitchinHD", a VRChat world featuring an interactive potion brewing system and fishing mechanics. This file provides context and coding guidelines for AI assistants working with this codebase.

## Project Overview

**Project Type**: Unity VRChat World (UdonSharp)
**Primary Systems**: 
- Potion brewing and alchemy system
- Interactive fishing mechanics
- Recipe discovery and progression
- Multiplayer synchronization

**Key Features**:
- Complex potion crafting with reagent mixing ratios
- Recipe unlocking system with fanfare effects
- Throwable and drinkable potion effects
- Fish behavior and catch mechanics
- Player inventory and storage systems

## Architecture & Core Systems

### Potion System Architecture
The potion system is the core mechanic, built around several key components:

- **Cauldron**: Central brewing station with recipe matching and ratio checking
- **Recipe**: Defines potion formulas with reagents and proportions
- **ReagentBottle**: Containers for potion ingredients
- **CauldronRecipe**: Runtime recipe tracking during brewing
- **Recipes**: Collection manager for all available recipes

### UdonSharp Integration
This project heavily uses UdonSharp for VRChat world scripting:
- All interactive components inherit from `UdonSharpBehaviour`
- Network synchronization using `[UdonSynced]` attributes
- Manual sync mode with `RequestSerialization()` calls
- Custom network events for multiplayer interactions

## Coding Standards & Conventions

### UdonSharp Specific Guidelines

**Synchronization Patterns**:
```csharp
[UdonBehaviourSyncMode(BehaviourSyncMode.Manual)]
public class ExampleClass : UdonSharpBehaviour
{
    [UdonSynced] public float syncedValue;
    
    public void UpdateValue(float newValue)
    {
        if (Networking.IsOwner(gameObject))
        {
            syncedValue = newValue;
            RequestSerialization();
        }
    }
}
```

**Network Events**:
- Use `SendCustomNetworkEvent(NetworkEventTarget.All, nameof(MethodName))` for multiplayer events
- Always check ownership before modifying synced variables
- Use `Networking.SetOwner()` when necessary

**VRChat Integration**:
- Always include proper VRChat SDK imports: `VRC.SDKBase`, `VRC.Udon`
- Use VRC persistence system for player data: `VRC.SDK3.Persistence`
- Implement proper player join/leave handling with `OnPlayerJoined`/`OnPlayerLeft`

### Class Structure Patterns

**Recipe System Classes**:
- Recipe classes should inherit from `UdonSharpBehaviour`
- Include proper serialization for network sync
- Use clear reagent checking and ratio validation methods
- Implement unlock mechanics with audio feedback

**Effect Classes** (like FreezingFlask):
- Inherit from appropriate base classes (`ShatterEffect` for throwable potions)
- Override virtual methods (`OnShatter`, `BypassShatter`)
- Include proper object pooling for performance
- Use Physics.OverlapSphere for area effects

**UI and Interaction Classes**:
- Handle both VR and desktop interaction patterns
- Include proper null checks for components
- Use delayed events for UI updates (`SendCustomEventDelayedFrames`)

### Performance Considerations

**Object Pooling**:
- Use VRCObjectPool for frequently spawned objects
- Always check if spawn was successful (`pool.TryToSpawn()`)
- Set proper ownership for pooled objects

**Update Loops**:
- Minimize expensive operations in Update()
- Use events or delayed events for complex calculations
- Cache component references in Start()

**Networking**:
- Minimize network traffic with smart synchronization
- Use local checks before network events
- Batch related changes together

## When Working with This Codebase

1. **Always consider multiplayer implications** - This is a VRChat world
2. **Understand the recipe system** - Central to the gameplay experience  
3. **Follow UdonSharp patterns** - Different from standard Unity C#
4. **Test networking thoroughly** - Synchronization is critical
5. **Maintain performance** - VRChat has strict limits
6. **Consider VR usability** - Design for both VR and desktop users
7. **Preserve the magical theme** - This is a fantasy potion brewing world
